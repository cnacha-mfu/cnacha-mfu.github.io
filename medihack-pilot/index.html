Pilot Testing for HealthTech

Which AI hardware should the hospital buy? The three prototypes (CareMind, Mali and CURA AI) need AI hardware inside the MFU Medical Center, so patient data never leaves the hospital network (PDPA). There are two realistic ways to do it.

Recommendation

For the pilot, buy Option A: two DGX Sparks, both running production at the same time. Unit 1 runs CareMind and unit 2 runs the Mali booth and CURA AI, so the booth never waits behind a handover note. CareMind uses only 25–40% of its unit at shift change, and most notes take 6–11 seconds, within the 5–10 second target. It is the cheaper option at Thai retail prices.

Option B, one GPU server, is the better buy only if a hospital-wide rollout is likely within 3 years. Option A would then have to buy a GPU server (or four more Sparks) anyway, so B ends up cheaper. See the scale-up plan below.

Scaling Option A

Can we scale by adding more DGX Sparks?

Yes. Each extra Spark adds about 9–10 notes a minute, and CareMind's proxy spreads notes across all units behind one address. More units don't make a single note faster: one note on a Spark always takes about 6–11 seconds. They stop notes from queuing, which is what pushes peak times to ~24 seconds.

Adding Sparks is the right move for a small step, such as a third unit for about 10 wards. For the whole hospital it is the most expensive route, gives slower notes, and leaves six boxes to power (~1.5 kW), patch and monitor. The Spark's 200 Gb port can join two units to run one very large model; that is for model size, and does not make the 8B models used here faster.

Why speed differs

Speed comes from memory bandwidth, not memory size

To write each word, an AI model reads all of its weights from memory, so how fast the memory can be read sets how fast text appears. All three prototypes together need only about 38 GB, which any 48 GB card holds. The Spark's 128 GB does not make it faster.

CareMind, checked in detail

Does the DGX Spark really work for CareMind?

Yes, at about today's speed.

Everything CareMind runs on the AI machine works on the Spark unchanged: Ollama, the Caddy security proxy, and a small Python service that uses no extra libraries. The app and its Thai OCR run on the separate x86 server.

Not faster, but enough for 2–3 wards.

The Spark writes text more slowly than today's lab GPU but reads CareMind's long prompts much faster, so the two roughly cancel out. In the pilot most notes run one at a time and stay within the target. Only when four notes queue on one unit does each take about 24 seconds, as on today's machine.

Decisions

  • Confirmed

    No spare server at MFU IT or the hospital, so the services server is bought. It is already in every total.

  • Confirmed

    Pilot scope: CareMind on 2–3 wards, one Mali booth.

  • Confirmed

    Under Option A, both Sparks run production at the same time: unit 1 CareMind, unit 2 Mali and CURA AI.

  • Open

    Option A or B? Recommendation for the pilot: A. If A, the Mali team tests the speech recogniser on a loaner Spark for 2–3 days before acceptance.

  • Open

    How likely is a hospital-wide rollout (about 15 wards) within 3 years? If likely, Option B is cheaper overall by ฿170,000–370,000.

  • Open

    Confirm the operating-cost basis: US$125 per Claude account per month, and ฿15,000 per team per month.

  • Open

    When must it be running? E-bidding takes 45–90 days from the TOR, and both product types have had 4–8 week stock delays.

  • Open

    Who owns the equipment after the pilot, MFU or the medical center? That decides which office issues the TOR.
